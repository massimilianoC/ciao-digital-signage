# Community Guidelines

This document defines how we collaborate, where discussions happen, and how moderation is handled.

## Community Goals

- Keep technical discussion constructive and searchable.
- Welcome contributors with different skill levels.
- Maintain a respectful and safe environment.

## Primary Channels

1. GitHub Issues
   - For bugs, feature requests, and implementation tasks.
2. GitHub Discussions
   - For ideas, architecture questions, and community Q&A.
3. Pull Requests
   - For proposed code and documentation changes.

## Optional External Channels

- Discord: good for onboarding, community chat, and quick support.
- Reddit: good for visibility and periodic updates, not for support tracking.

Recommendation:

- Start with GitHub-first workflow.
- Add Discord only when there is recurring real-time community demand.
- Use Reddit mainly as broadcast to drive people to GitHub.

## Moderation Principles

- Follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
- Remove harassment, spam, or abusive content.
- Keep technical decisions documented on GitHub for transparency.

## Maintainer Response Targets

- New issues/discussions acknowledgment: within 5 business days.
- Labeling and triage: as soon as possible after acknowledgment.
- Escalation to milestone planning: when the issue is accepted.

## Community-to-Roadmap Flow

1. Idea reported in Discussions or Issues.
2. Maintainer triages and labels.
3. If accepted, issue is linked to milestone in [MILESTONES.md](MILESTONES.md).
4. Release visibility is tracked in [CHANGELOG.md](CHANGELOG.md).
